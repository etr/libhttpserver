1. [ ] **performance-reviewer** | `src/detail/io_external_adapter.cpp:169` | algorithmic-complexity
   find_registration_locked scans the entire connections_ map for every host event while holding mu_. For C live registrations and E callbacks, dispatch adds O(E*C) lookup work, including unknown, stale, duplicate and permitted all-false callbacks. A lookup-only probe rebuilding this adapter at -O2 measured 2.09 ms at 1,024 registrations/events, 24.50 ms at 4,096, 65.52 ms at 8,192, and 175.86 ms at 16,384. The server permits a configurable connection budget up to 1,048,576. These traversals delay other work on the controlling host loop and contend with worker submissions. The probe uses sentinel handles and performs no network I/O; it isolates the new lookup rather than measuring end-to-end throughput. The existing pending-operation directional scans are inherited fallback behavior.
   *Recommendation:* Index live registrations by opaque socket key (mapping to private connection ID or lifetime), then validate generation, published state and retirement after an expected O(1) lookup. Erase index entries on retirement/pruning so indexing does not reintroduce tombstone growth. Preserve the generation/reopen tests and compare 1K/4K/16K callback batches after indexing.
